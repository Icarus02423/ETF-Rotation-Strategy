# ETF轮动策略实验项目

这是一个用于研究 ETF 动态轮动策略的回测项目。项目把实验参数、输出路径、
数据准备、参数调优和正式回测分开管理，目的是让每组实验都能被准确复现，
并避免靠手工修改脚本来切换实验条件。

当前版本是“基础对照实验”版本。它会系统比较：

- 月度更新与日度更新；
- 不过滤、仅 BIAS、仅波动率、BIAS 与波动率同时启用；
- 三个聚类阈值；
- 两种趋势因子；
- 五个趋势窗口；
- 十种错峰周期。

## 一、当前实验设计

```text
ETF总表与基准数据
        │
        ▼
46项上游数据准备
        │
        ├────────► 1200项参数调优
        │              │
        │              └─ 当前只生成诊断热力图，不会自动修改正式回测参数
        │
        └────────► 2400组正式回测
                       └─ 当前使用固定的过滤参数初值
```

### 1. 正式回测矩阵

| 实验维度 | 取值 | 数量 |
| --- | --- | ---: |
| ETF 池更新频率 | `monthly`、`daily` | 2 |
| 过滤状态 | `base`、`bias_only`、`volatility_only`、`bias_and_volatility` | 4 |
| 聚类相关性阈值 | `0.7`、`0.8`、`0.9` | 3 |
| 趋势因子 | `return_r2`、`return_vol` | 2 |
| 趋势窗口 | `10`、`15`、`20`、`40`、`60` 个交易日 | 5 |
| 错峰周期 | `1` 至 `10` 个交易日 | 10 |

因此正式实验共有：

```text
2 × 4 × 3 × 2 × 5 × 10 = 2400 组 ExperimentCase
```

每组实验都会分别运行收盘价成交和次日 VWAP 成交两种方式。

实验维度的唯一机器可读来源是 `实验配置.py`。如果以后改变参数范围，应修改
该文件，而不是在多个运行脚本里重复维护另一份参数表。

### 2. 四种过滤状态

| 过滤状态 | BIAS 过滤 | 波动率过滤 | 对应调优 |
| --- | --- | --- | --- |
| `base` | 关闭 | 关闭 | 不需要过滤参数调优 |
| `bias_only` | 启用上限过滤 | 关闭 | BIAS 参数调优 |
| `volatility_only` | 关闭 | 启用，保留高波动指数 | 波动率参数调优 |
| `bias_and_volatility` | 启用上限过滤 | 启用，保留高波动指数 | 分别进行两类条件调优 |

`bias_and_volatility` 当前不是同时搜索四个参数的联合调优：

- 调 BIAS 时，波动率参数固定为 18 日、保留 55%；
- 调波动率时，BIAS 参数固定为 36 日、上限 9%。

### 3. 两种趋势因子

- `return_r2`：窗口收益率 × 线性回归的决定系数 `R²`，同时衡量趋势方向、
  强度和稳定性；
- `return_vol`：窗口收益率 ÷ 由窗口内日收益率样本标准差换算出的窗口波动率，
  用于衡量风险调整后的趋势强度。

### 4. 单组策略流程

1. 按月度或日度频率建立 ETF 池；
2. 用指数收益率相关性进行完整链接聚类，并选取代表指数；
3. 计算两种趋势因子；
4. 按实验的过滤状态，先对候选指数进行 BIAS 和/或波动率过滤；
5. 在过滤后的指数中按指定趋势因子排名，选择前 10%；
6. 将指数映射到成交量最大的跟踪 ETF；
7. 按收盘价或次日 VWAP 成交，并计入买卖各 0.1% 的交易成本；
8. 错峰周期为 `d` 时，将资金分为 `d` 个账户，每天轮换一个账户，
   每个账户持有 `d` 个交易日。

当前策略不要求趋势窗口收益率必须为正。

## 二、三个批量运行入口

| 入口 | 负责的内容 | 不负责的内容 |
| --- | --- | --- |
| `运行全部数据准备.py` | 生成全部频率、阈值和趋势窗口所需的上游数据 | 不下载 ETF 总表和基准数据；不调优；不回测 |
| `运行参数调优.py` | 安全预览、筛选并串行运行 BIAS/波动率参数网格 | 不自动选择最优参数；不写回正式回测 |
| `运行全部回测.py` | 串行运行 2400 组正式回测，并跳过完整结果 | 不准备上游数据；不运行参数调优 |

三个入口故意保持独立。目前不提供把数据准备、722 万余次调优模拟和 2400 组
正式回测全部绑在一起的“一键总入口”。

### 1. 全部数据准备

数据准备共 46 个任务，依赖顺序如下：

```text
ETF初筛 2项
  → 指数收益率准备 2项
  → 指数聚类 6项
  → 趋势行情准备 6项
  → 趋势因子计算 30项
```

运行前必须已经存在非空的 `outputs/etf_data/etf_data.csv`。

```bash
.venv/bin/python 运行全部数据准备.py
```

这个命令会立即开始执行，没有预览模式。任一任务失败时会停止，不会继续执行
后面的依赖任务。

### 2. 参数调优

每种调优类型都有 600 个外层任务：

```text
2种更新频率 × 2种兼容过滤状态 × 3个阈值 × 5个趋势窗口 × 10种错峰周期
= 600项
```

BIAS 与波动率两类合计 1200 项。每项同时计算两个趋势因子和两种成交方式，
并生成 4 张热力图。完整矩阵预计进行 7,221,600 次逐日收益模拟，生成
4,800 张热力图。

不带参数时只显示帮助，不会运行调优：

```bash
.venv/bin/python 运行参数调优.py
```

预览全部 1200 项：

```bash
.venv/bin/python 运行参数调优.py --all
```

预览一组精确实验：

```bash
.venv/bin/python 运行参数调优.py \
  --tuning-type bias \
  --frequency monthly \
  --profile bias_only \
  --threshold 0.8 \
  --trend-window 40 \
  --stagger-days 1
```

确认范围无误后，才在同一条命令末尾增加 `--execute`。完整调优必须明确使用：

```bash
.venv/bin/python 运行参数调优.py --all --execute
```

这是一个计算量非常大的命令，不建议在尚未确定研究方法时直接运行。默认会
跳过四张热力图均完整且没有 `.incomplete` 标记的任务；`--force` 只能和
`--execute` 一起使用，用于强制重跑选中任务。不要同时启动两个进程运行同一组
调优任务。

### 3. 全部正式回测

```bash
.venv/bin/python 运行全部回测.py
```

这个命令会立即检查并运行全部 2400 组实验，没有预览模式。每组实验的两种成交
方式合计应生成 20 个非空文件；完整且没有 `.incomplete` 标记的实验会自动跳过。
运行中断或失败后，可修复问题并执行同一命令继续。

算法发生变化、需要忽略已有结果并重跑全部实验时才使用：

```bash
.venv/bin/python 运行全部回测.py --force
```

## 三、参数调优与正式回测的当前边界

> 重要：参数调优结果目前不会自动进入正式回测。

当前调优脚本只保存 4 张 PNG 热力图，不保存完整矩阵 CSV、最优参数 JSON 或
可供正式回测读取的参数清单。正式回测仍使用代码中的初始过滤参数：

| 参数 | 当前值 |
| --- | ---: |
| BIAS 均线窗口 | 36 日 |
| BIAS 上限 | 9% |
| 波动率日收益窗口 | 18 日 |
| 高波动指数保留比例 | 55% |

因此，当前 2400 组正式回测是统一初始参数下的基础对照实验，不应描述成“使用
每组最优参数的回测”。在自动衔接前还需要先确定：

- 用哪一个趋势因子和成交方式对应的结果选参；
- 用累计收益、风险调整收益还是其他指标选参；
- 是否划分训练期和样本外测试期，避免用测试期数据反向选参；
- `bias_and_volatility` 使用顺序条件调优还是联合调优；
- 参数变化后如何给输出记录参数指纹，避免旧结果被误判为完成。

合理的后续顺序是：先保存机器可读调优矩阵，再确定选参规则并生成参数清单，
最后让正式回测显式读取该清单。

## 五、项目结构

```text
ETF轮动策略/
├── 实验配置.py                  # 实验维度的唯一配置来源
├── 输出路径.py                  # 所有正式输出路径的唯一来源
├── 运行全部数据准备.py          # 46项上游任务入口
├── 运行参数调优.py              # 可预览、可筛选的调优入口
├── 运行全部回测.py              # 2400组正式回测入口
├── scripts/
│   ├── ETF数据下载/
│   │   ├── 下载ETF数据.py
│   │   └── 下载基准数据.py
│   ├── ETF池筛选/
│   │   ├── ETF初筛.py
│   │   ├── 指数收益率准备.py
│   │   └── 指数聚类筛选.py
│   ├── ETF趋势策略回测/
│   │   ├── 趋势行情准备.py
│   │   ├── 趋势因子计算.py
│   │   └── 交易策略回测.py
│   └── 策略参数调优/
│       ├── BIAS参数调优.py
│       └── 波动率参数调优.py
├── tests/                       # 离线单元测试
├── outputs/                     # 输入数据、中间数据和实验输出
├── requirements.txt             # Python依赖版本
├── pyproject.toml               # 项目名称、版本和Python版本等元数据
└── README.md                    # 面向使用者的项目说明
```

各目录中的 `__init__.py` 让 Python 能把该目录作为包导入。它不会自动运行目录下
的所有脚本。真正的批量执行由项目根目录的三个“运行”脚本负责。

`pyproject.toml` 当前只记录项目元数据，也不是运行入口。

## 六、建议运行顺序

1. 创建虚拟环境并安装依赖；
2. 配置本机 `.env`；
3. 单独准备 ETF 总表和基准数据；
4. 运行完整离线测试；
5. 运行全部数据准备；
6. 先预览并小范围运行参数调优；
7. 明确选参方法后，再决定运行基础固定参数回测还是后续的优化参数回测。

安装依赖：

```bash
.venv/bin/python -m pip install -r requirements.txt
```

运行全部测试：

```bash
.venv/bin/python -m unittest discover -s tests -v
```

下载脚本不包含在“全部数据准备”入口中，需要时单独执行：

```bash
.venv/bin/python scripts/ETF数据下载/下载ETF数据.py
.venv/bin/python scripts/ETF数据下载/下载基准数据.py
```

## 七、数据、凭据与 Git

iFinD 凭据只保存在项目根目录的 `.env` 文件中：

```text
IFIND_USERNAME=...
IFIND_PASSWORD=...
IFIND_REFRESH_TOKEN=...
```

`.env` 已被 Git 忽略，不应提交到 GitHub。

`.gitattributes` 中明确列出的几个大型 ETF 数据文件使用 Git LFS；其余输出文件
仍按普通 Git 文件管理。GitHub 上的结果文件可能很多，正式运行大矩阵前应先确认
磁盘空间、预计耗时和提交范围。
